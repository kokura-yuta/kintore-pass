# 友達機能 V2

入口：アプリのマイページ → 友達。Freeでも利用可能。公開タイムラインなし。

## DB/API

既存usersのUUIDを検索用IDとして利用。0019でfriend_settings、friendships、friend_action_quotasを追加。全FKはアカウント削除時CASCADE。目標履歴は運営分析用で友達APIに含めない。

`GET /api/friends` は本人の設定と申請・友達一覧（最新200件）。`GET /api/friends?userId=UUID` は承認済み関係を同じ記録取得SQL内で検証。`POST` はsettings/search/request/accept/reject/cancel/remove。本人はClerk IDからDBで確定し、クライアント指定actorを受け付けない。

## 公開・不正防止

- 初期はメール検索OFF、記録共有OFF。表示名は友達向けの任意名、未設定は匿名の名称。本名を自動公開しない。
- ID・メールは完全一致のみ。メールは本人の許可が必要で、検索結果にもログにも返さない。検索30回/日・申請20回/日をJSTでDB原子的に制限。
- 双方向の申請を勝手に承認しない。承認/拒否は受信者のみ、取消は送信者のみ、解除は承認済みの当事者のみ。拒否・取消後の再申請は24時間待機。
- 承認済み＋共有ONの場合のみ最新20保存記録を返す。実施日・部位・種目・重量・回数・セット以外（メモ/調子/時間/写真/体重/体脂肪率/会話/食事）は返さない。
- 友達解除または共有OFFで新しいAPI取得を拒否/非公開にする。閲覧済み画面やスクリーンショットの消去までは保証しない。
- 友達への記録変更/削除APIを作らず、既存本人限定APIも維持。公開設定と関係はprivate,no-store。

## 検証・反映

単体 `tests/retention-v2.test.mjs`、実DB `scripts/test-v2-db.mjs`（専用期限付き検証ブランチのURLを隠しstdinで渡す）。認可・状態遷移・共有OFF・解除・最小項目・同時検索上限と目標履歴を実DBで確認。架空利用者は検証ブランチのみ。

Web/アプリのプライバシー説明を更新。アプリ画面は新しいTestFlightビルドが必要。実機で2アカウントの申請、承認、共有設定、解除、再起動を確認してから一般公開する。App Storeのプライバシー回答・審査説明にも共有機能を反映する。運営集計と友達の公開データは混同しない。
