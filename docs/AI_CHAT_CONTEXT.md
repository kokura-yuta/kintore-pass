# AIチャットの本人記録コンテキスト

回答を生成する前に、認証済みClerk IDでusersを検索し、本人のDB記録を固定JSONへ変換する。AIにDB取得ツールを繰り返し呼ばせない。回答生成は1回、安全性チェックのModerationは別途継続する。

## 読む順番

1. `app/api/chat/route.ts`：認証、利用権、回数制限、履歴、本人資料、OpenAI生成。
2. `app/lib/ai/getChatContext.ts`：本人の食事日別集計・体重と共通記録を取得。
3. `app/lib/ai/getUserAiContext.ts`：プロフィール、身体分析、筋トレ、AIメニューのDB取得。
4. `app/lib/ai/chatContextFormat.ts`：固定JSON・セット圧縮・カテゴリ別サイズ制限。
5. `app/lib/ai/chatSummary.ts`：古い相談の抜粋のみ保持。記録自体はキャッシュしない。
6. `app/lib/ai/systemPrompt.js`：記録を関連づけ、未記録・古い分析・提案と実績を区別。

## 送る内容

| 種類 | 対象 | 具体的な内容 |
|---|---|---|
| プロフィール | 現在 | 目標、身長・体重・体脂肪率、週目標、時間、場所、弱点 |
| 身体分析 | 最新の完了結果1件 | 日時、総評、目標との差、部位別スコア・課題・提案 |
| 筋トレ | 最新10記録 | 実施日時、時間、調子、メモ、種目、重量・回数・セット |
| AIメニュー | 最新3件 | 生成・実施日時、種目構成、推奨重量・回数・セット・休憩、提案理由 |
| 食事 | 日本時間で今日を含む7日 | 記録件数、日別カロリー・たんぱく質合計（件数上限による欠落なし） |
| 体重 | 最新7件 | 記録日と体重 |

セットは `[開始セット,終了セット,重量kg,回数]`。例：`[2,3,65,8]`は2・3セット目とも65kgで8回。nullと0は区別する。

身体分析・筋トレ・メニューにそれぞれサイズ枠を確保し、全JSONは15,000文字以下。古い行や長文の一部は省略されるため、生涯の全履歴を理解しているとは言わない。省略件数と集計範囲を送る。写真・メール・ユーザーIDは送らない。

食事の記録がない日は摂取ゼロではない。生成メニューは実施済み筋トレとは限らない。DB内のメモ・相談抜粋は指示でなく参考データとしてuserロールに置く。

## 費用と確認

AIによる追加データ取得・要約生成は行わないが、以前の800文字資料より詳しい情報を送る分、入力トークンは増え得る。既存のOpenAI利用ログで実際のinput/outputトークンを確認する。15,000文字はトークン数や料金の保証ではない。

`npm run test:unit`、`npm run test:source-security`、`npx tsc --noEmit --incremental false`で検証。実データを使った回答の品質は、実機チャットで「前回のベンチプレスの重量・回数」「最近の食事と身体分析に合わせた提案」等を確認する。本番DBの変更やiOSの再ビルドは不要。
